# master-node

Master узел распределенной вычислительной системы Grid System. Отвечает за загрузку данных, генерацию подзадач, распределение задач между worker-ами, сбор результатов и поиск оптимального решения.

## Структура

```
master-node/
├── master_node/
│   ├── __init__.py
│   ├── main.py                 # Точка входа
│   ├── generator.py            # Генерация подзадач
│   ├── dispatcher.py           # Диспетчер воркеров
│   ├── console.py              # Консольный интерфейс
│   ├── config.py               # Конфигурация
│   ├── log_manager.py          # Управление логами
│   ├── persistent_storage.py   # Хранение состояния
│   ├── _logs/                  # Директория логов
│   │   ├── master.log
│   │   ├── generator.log
│   │   └── dispatcher.log
│   └── _processing/            # Данные вычислений
│       ├── completed_subtasks.txt
│       ├── subproblems.json
│       └── results.json
└── setup.py                    # Установочный файл
```

## Компоненты

### generator.py - Генератор подзадач

Вычисляет количество возможных размещений для каждого слова и группирует их в подзадачи.

**Класс `Generator`**

| Метод | Описание |
|-------|----------|
| `compute_placement_counts()` | Вычисление количества размещений для каждого слова |
| `create_subproblems()` | Создание подзадач на основе коэффициента сложности |

**Алгоритм группировки:**
- Слова сортируются по убыванию сложности
- В одну подзадачу добавляются слова, пока суммарная сложность ≤ коэффициенту
- Слова с индивидуальной сложностью > коэффициента получают отдельную подзадачу

### dispatcher.py - Диспетчер воркеров

Управляет пулом воркеров, распределяет задачи, обрабатывает heartbeat, перераспределяет задачи при отказах.

**Класс `Dispatcher`**

| Метод | Описание |
|-------|----------|
| `register_worker(address)` | Регистрация нового воркера |
| `submit_subproblem(subproblem)` | Отправка подзадачи на выполнение |
| `update_heartbeat(worker_id, status, task)` | Обновление heartbeat воркера |
| `get_worker_status()` | Получение статуса всех воркеров |

**Фоновые задачи:**
- `_worker_loop()` - Основной цикл распределения задач
- `_heartbeat_monitor()` - Мониторинг heartbeat воркеров

### console.py - Консольный интерфейс

Интерактивное меню для управления вычислениями и мониторинга состояния.

**Класс `Console`**

| Метод | Описание |
|-------|----------|
| `run()` | Запуск консольного интерфейса |
| `show_menu()` | Отображение текущего меню |
| `handle_choice(choice)` | Обработка выбора пользователя |
| `view_log(component)` | Просмотр лога с пагинацией и автообновлением |

**Меню:**
- Настройки
- Запуск/статус вычислений
- Просмотр решения
- Просмотр подзадач
- Просмотр воркеров
- Просмотр логов

### log_manager.py - Управление логами

Создает отдельные логгеры для каждого компонента и обеспечивает ротацию логов.

**Класс `LogManager`**

| Метод | Описание |
|-------|----------|
| `get_logger(component)` | Получение логгера для компонента |
| `read_log(component, lines, offset)` | Чтение лога с пагинацией |

**Компоненты логирования:**
- `master` - Основные события мастера
- `generator` - Процесс генерации подзадач
- `dispatcher` - Распределение задач и коммуникация с воркерами

### persistent_storage.py - Хранение состояния

Сохраняет состояние вычислений между запусками для возможности восстановления.

**Класс `PersistentStorage`**

| Метод | Описание |
|-------|----------|
| `save_subproblems(subproblems)` | Сохранение подзадач |
| `load_subproblems()` | Загрузка подзадач |
| `save_completed_subtask(subproblem_id)` | Сохранение ID выполненной подзадачи |
| `load_completed_subtasks()` | Загрузка выполненных подзадач |
| `save_results(results)` | Сохранение результатов |
| `load_results()` | Загрузка результатов |

### config.py - Конфигурация

Хранит настройки приложения.

**Класс `Config`**

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `matrix_path` | Путь к файлу матрицы | - |
| `words_path` | Путь к файлу словаря | - |
| `coefficient` | Коэффициент сложности | 1000 |
| `worker_timeout` | Таймаут воркера (сек) | 30 |
| `task_timeout` | Таймаут задачи (сек) | 60 |
| `dispatcher_poll_timeout` | Таймаут опроса очереди (сек) | 1 |
| `no_worker_sleep` | Пауза при отсутствии воркеров (сек) | 5 |
| `master_host` | Адрес master HTTP сервера | 127.0.0.1 |
| `master_port` | Порт master HTTP сервера | 8080 |

### main.py - Точка входа

Главный класс Master, объединяющий все компоненты и управляющий вычислительным процессом.

**Класс `Master`**

| Метод | Описание |
|-------|----------|
| `load_matrix(path)` | Загрузка матрицы из файла |
| `load_words(path)` | Загрузка слов из файла |
| `start_computation()` | Запуск вычислений |
| `compute_covering(placements)` | Жадный алгоритм покрытия |
| `get_status()` | Получение статуса вычислений |
| `get_subproblem_info(sub_id)` | Получение информации о подзадаче |

## API Endpoints

| Endpoint | Method | Description | Request Body | Response |
|----------|--------|-------------|--------------|----------|
| `/register` | POST | Регистрация воркера | `{"address": "http://host:port"}` | `{"worker_id": int}` |
| `/heartbeat` | POST | Heartbeat от воркера | `{"worker_id": int, "status": str, "current_task": int}` | `200 OK` |
| `/workers` | GET | Список воркеров | - | `{worker_id: {...}}` |

## Запуск

```bash
python -m master-node
```

При запуске потребуется ввести:
- Путь к файлу матрицы
- Путь к файлу словаря
- Коэффициент сложности

## Директории

### `_logs/`
Файлы логов компонентов. Поддерживается ротация: 5 файлов по 10 МБ.

### `_processing/`
Данные вычислений:
- `completed_subtasks.txt` - ID выполненных подзадач (по одному на строку)
- `subproblems.json` - Сериализованные подзадачи
- `results.json` - Сериализованные результаты
